# Effect Form

A React user-management demo built with Effect, TanStack Router/Form/Table, and Vite+. It loads users from a JSONPlaceholder-compatible API, supports a filterable, sortable list, and demonstrates optimistic user creation. The home page also has a natural-language command center for navigating to and filtering users; `/about` is a placeholder route.

## Features and behavior

- The user list reads `GET /users`. The creation form posts to `POST /users` and shows an optimistic entry while the request is pending. **The form is shown only when the PostHog `allow-user-creation` feature flag is enabled.** JSONPlaceholder accepts POST requests but does not persist new users, so a refresh will not retain them.
- Filter users with the `filter` URL query parameter (or the filter input). Supported fields are `name`, `username`, and `email`; free text, `*` wildcards, uppercase `AND`/`OR`, and parentheses are supported. For example: `?filter=email%3A*@example.com`.
- Open the command center with **Mod+K**. It uses Claude to turn prompts into navigation/filter actions. This requires an Anthropic API key and a working `/anthropic` proxy; see [configuration](#configuration).
- The account menu offers light/dark/system themes and debug toggles for simulated API latency/errors and OTLP tracing/logging. Changing a debug toggle reloads the page. Analytics is opted out until the visitor accepts the cookie banner.

## Local development

Use Node.js and the pinned `pnpm@12.16.1` from `package.json` (Corepack can supply pnpm). Install dependencies, copy the example configuration, and start Vite+:

```sh
corepack enable
pnpm install --frozen-lockfile
cp .env.example .env.local
pnpm exec vp dev
```

The dev server URL is printed by Vite+. To route API requests through the included dev proxy, set `VITE_API_BASE_URL=/api` in `.env.local`; the example file instead points directly to JSONPlaceholder. For AI prompts, set `VITE_ANTHROPIC_API_KEY` in `.env.local` and restart the dev server. **Only use a development/test key:** the Vite dev proxy uses this key to authenticate requests, and `VITE_` variables are not a safe place for production secrets. Do not commit `.env.local`.

An optional Nix shell is provided for **aarch64-darwin** (Apple Silicon), with Node.js 26 and pnpm. Run `nix develop`, or approve `.envrc` with `direnv allow` to enter it automatically. `.envrc` puts `node_modules/.bin` on `PATH`, allowing `vp dev` in place of `pnpm exec vp dev`. On other platforms, install Node.js and Corepack separately.

## Configuration

Vite reads `.env.local` and `VITE_` variables at build/dev-server time:

| Variable | Purpose |
| --- | --- |
| `VITE_API_BASE_URL` | Base URL for `/users` and `/posts` requests; required by the Effect API client. Use `/api` with the provided proxies. |
| `VITE_OTLP_BASE_URL` | OTLP HTTP base URL for traces and logs when OpenTelemetry is enabled; defaults to `/otlp`. |
| `VITE_PUBLIC_POSTHOG_KEY` | PostHog project key for analytics and the `allow-user-creation` feature flag. |
| `VITE_PUBLIC_POSTHOG_HOST` | PostHog endpoint; use `/ingest` with the provided proxies. |
| `VITE_ANTHROPIC_API_KEY` | Used by the **development** `/anthropic` proxy for command-center requests. |
| `VITE_APP_VERSION` | Version attached to telemetry resources; defaults to `0.0.0`. |

The dev server proxies `/api` to JSONPlaceholder, `/otlp` to `localhost:4318`, `/ingest` to PostHog EU, and `/anthropic` to Anthropic. The Anthropic model is `claude-haiku-4-5`. Without a working AI proxy/key, the app still loads but command-center requests fail. Without a configured PostHog feature flag, the creation form may not appear.

## Project layout

- `src/routes/` defines the home and about pages; `src/routeTree.gen.ts` is generated by TanStack Router and should not be edited manually.
- `src/domains/user/` contains the user form, list, filter grammar, Effect service, and reactive atoms. `src/domains/search/` handles the command center and navigation tool.
- `src/shared/api/` holds the HTTP client, typed errors, and optional failure/latency simulation.
- `src/infrastructure/runtime.ts` composes the Effect services; `src/infrastructure/telemetry.ts` enables OTLP export when selected in the account menu.
- `src/shared/components/ui/` contains reusable UI primitives; `src/index.css` defines Tailwind styling.

## Checks and tests

Run commands through the pinned Vite+ binary (`vp` if the direnv shell is active, otherwise `pnpm exec vp`):

```sh
pnpm exec vp run build          # TypeScript project build + production bundle
pnpm exec vp check              # Format, lint, type-check, and test checks
pnpm exec vp test --project node
pnpm exec vp run test:browser
pnpm exec vp run test:coverage
```

Browser tests use Playwright. Install its browsers first with `pnpm exec playwright install chromium firefox webkit`. Browser tests run across Chromium, Firefox, and WebKit; coverage uses node tests and browser Chromium.

## Containers and observability

`docker-compose.yaml` starts an optional OpenTelemetry collector, Tempo, Loki, and Grafana (at <http://localhost:3001>). The collector accepts OTLP HTTP on port 4318. Start it with `docker compose up -d`, then enable **OpenTelemetry** in the account menu. For local development, set `VITE_OTLP_BASE_URL=/otlp` to send telemetry via the Vite proxy, or use the example's `http://localhost:4318` if your browser can reach the collector directly.

The production Dockerfile builds static assets and serves them from nginx over HTTPS (self-signed certificate by default). Build with proxy-relative URLs:

```sh
docker build \
  --build-arg VITE_API_BASE_URL=/api \
  --build-arg VITE_OTLP_BASE_URL=/otlp \
  --build-arg VITE_PUBLIC_POSTHOG_KEY=<your-posthog-key> \
  --build-arg VITE_PUBLIC_POSTHOG_HOST=/ingest \
  -t effect-form .

docker run -p 80:80 -p 443:443/tcp -p 443:443/udp \
  -e API_URL=https://jsonplaceholder.typicode.com/ \
  -e API_HOST=jsonplaceholder.typicode.com \
  -e OTLP_URL=http://host.docker.internal:4318/ \
  -e POSTHOG_REGION=eu \
  effect-form
```

Visit <https://localhost> and accept the self-signed certificate warning for local testing. The trailing slashes on `API_URL` and `OTLP_URL` matter: nginx strips the `/api/` and `/otlp/` prefixes when forwarding. For production TLS, mount a directory containing `cert.pem` and `key.pem` at `/etc/nginx/certs:ro` and supply your own upstream endpoints. Docker/nginx proxies `/api`, `/otlp`, and `/ingest` **but not `/anthropic`**: the AI command center needs a separately configured, server-side authenticated Anthropic proxy to work in a deployed build; do not expose its API key as a client build argument.
