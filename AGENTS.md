# AGENTS.md

## Commands

- Use Bun for package scripts; `bun.lock`, Docker, and Dependabot all identify this repo as Bun-based.
- Install with `bun install --frozen-lockfile` when reproducing Docker/CI-like dependency resolution.
- Dev server: `bun run dev`.
- Build/typecheck: `bun run build` (`tsc -b` then `vite build`).
- Lint: `bun run lint`; GitHub annotation format: `bun run lint:github`.
- Format: `bun run fmt` (`oxfmt --ignore-path=.oxfmtignore`), not Prettier.
- Node tests: `bun run test` for `src/**/*.test.ts`.
- Browser tests: `bun run test:browser` for `src/**/*.test.tsx`; uses Vitest browser mode with Playwright across Chromium, Firefox, and WebKit.
- Coverage: `bun run test:coverage`; coverage intentionally runs only the node project plus browser Chromium.

## Architecture

- Single Vite React app; entrypoint is `src/main.tsx`, router wiring is `src/router.ts`, file routes live in `src/routes`.
- `src/routeTree.gen.ts` is generated by TanStack Router. Do not edit it directly; change `src/routes/*` and let the Vite router plugin regenerate it.
- Runtime/service wiring is Effect-based in `src/infrastructure/runtime.ts`; domain atoms should use the shared `runtimeAtom`.
- API access goes through `src/shared/api/client.ts` (`ApiLive`) and prepends `VITE_API_BASE_URL`.
- Debug flags are persisted in localStorage keys `debug:simulation:v1` and `debug:otel:v1`; changing them reloads the page so the Effect layer graph is rebuilt.
- The command center uses Anthropic through the Vite `/anthropic` proxy and requires `VITE_ANTHROPIC_API_KEY` for successful AI calls.

## Env And Proxies

- Copy `.env.example` for local env names; important Vite vars are `VITE_API_BASE_URL`, `VITE_OTLP_BASE_URL`, `VITE_PUBLIC_POSTHOG_KEY`, `VITE_PUBLIC_POSTHOG_HOST`, `VITE_ANTHROPIC_API_KEY`, and `VITE_APP_VERSION`.
- Vite dev proxies `/api`, `/otlp`, `/ingest`, and `/anthropic`; Docker/nginx also proxies `/api`, `/otlp`, and `/ingest`.
- Docker build args set Vite-time URLs; Docker runtime env (`API_URL`, `API_HOST`, `OTLP_URL`, `POSTHOG_REGION`) is substituted into `nginx.conf`.

## Testing Notes

- Effect service tests use `@effect/vitest`, `it.effect`, and `TestClock.adjust` to skip simulated sleeps/timeouts.
- Browser component tests use `vitest-browser-react`; components depending on query params commonly need `NuqsTestingAdapter`.
- Test API services with `src/test/mock-client.ts` instead of real network calls.

## Style

- Imports, Tailwind classes, and `package.json` scripts are sorted by `oxfmt` config.
- `oxfmt` ignores `index.html`, `src/routeTree.gen.ts`, and `observability`.
- UI primitives live in `src/shared/components/ui`; this repo uses Base UI/shadcn-style components with Tailwind v4 tokens in `src/index.css`.

# Using Vite+, the Unified Toolchain for the Web

This project is using Vite+, a unified toolchain built on top of Vite, Rolldown, Vitest, tsdown, Oxlint, Oxfmt, and Vite Task. Vite+ wraps runtime management, package management, and frontend tooling in a single global CLI called `vp`. Vite+ is distinct from Vite, and it invokes Vite through `vp dev` and `vp build`. Run `vp help` to print a list of commands and `vp <command> --help` for information about a specific command.

Docs are local at `node_modules/vite-plus/docs` or online at https://viteplus.dev/guide/.

## Built-in Commands vs Scripts

`vp <name>` runs a built-in command. `vp run <name>` runs a `package.json` script or a `vite.config.ts` task. Scripts cannot overwrite built-ins, so `vp dev` and `vp run dev` may do different things. Check `package.json` and `vite.config.ts` first, and run `vp run <name>` when the project defines a script or task with that name.

## Tool Versions

Run `vp toolchain` to show versions and relationships in the active Vite+
release. Add a tool name to select part of the graph. For example, run
`vp toolchain vite`. Use `--global` to ignore the local `vite-plus` package. Use
`vp why <package>` to show the package-manager dependency graph.

## Review Checklist

- [ ] Run `vp install` after pulling remote changes and before getting started.
- [ ] Run `vp check` and `vp test` to format, lint, type check and test changes.
- [ ] Check if there are `vite.config.ts` tasks or `package.json` scripts necessary for validation, run via `vp run <script>`.
- [ ] If setup, runtime, or package-manager behavior looks wrong, run `vp env doctor` and include its output when asking for help.
